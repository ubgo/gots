# Architecture (Internal)

How gots works internally. For contributors and developers working on the codebase.

For user-facing docs, see [README.md](../README.md).

---

## Pipeline

```
gots.yaml          Go source files (.go)
    │                       │
    ▼                       ▼
┌────────┐          ┌──────────────┐
│ Config │          │  go/parser   │
│ Load() │          │  go/ast      │
└───┬────┘          └──────┬───────┘
    │                      │
    │  *Config             │  *ast.File
    │                      ▼
    │               ┌──────────────┐
    │               │    Parser    │
    │               │ parseType()  │
    │               │ parseConst() │
    │               └──────┬───────┘
    │                      │
    │                      │  *ParseResult
    │                      │  ├── []TypeDef
    │                      │  ├── []ConstDef
    │                      │  └── []StructDef
    │                      │
    ▼                      ▼
┌──────────────────────────────┐
│          Generator           │
│                              │
│  Phase 1: Typed constants    │
│  Phase 2: Type aliases       │
│  Phase 3: Untyped constants  │
│  Phase 4: Structs            │
└──────────┬───────────────────┘
           │
           ▼
      .ts output files
```

## Stage 1: Config Loading (`pkg/config`)

1. Reads `gots.yaml` from disk (`os.ReadFile`)
2. Unmarshals YAML into `Config` struct (`yaml.Unmarshal`)
3. Applies defaults for any unset fields (`applyDefaults`)

**Defaults applied:**

| Field | Default |
|---|---|
| `default_style` | `"union"` |
| `struct_tag` | `"json"` |
| `pointer_handling` | `"optional"` |
| `empty_interface` | `"unknown"` |
| `header` | `"// Code generated by gots. DO NOT EDIT."` |
| `type_map` | `{"time.Time": "string", "json.RawMessage": "unknown"}` |

## Stage 2: Parsing (`pkg/parser`)

Uses `go/parser.ParseFile` to build an AST, then walks it extracting declarations.

### How Go AST maps to our types

```
Go Source                     AST Node              Our Type
─────────────────────────────────────────────────────────────
type MessageRole string   →  GenDecl(TYPE)       →  TypeDef
                              └── TypeSpec
                                  ├── Name: "MessageRole"
                                  └── Type: Ident("string")

const (                   →  GenDecl(CONST)      →  []ConstDef
  MsgUser MsgRole = "u"      └── ValueSpec
)                                 ├── Names: ["MsgUser"]
                                  ├── Type: Ident("MsgRole")
                                  └── Values: [BasicLit("u")]

type User struct {        →  GenDecl(TYPE)       →  StructDef
  Name string `json:"n"`     └── TypeSpec
}                                 └── StructType
                                       └── Field
                                           ├── Names: ["Name"]
                                           ├── Type: Ident("string")
                                           └── Tag: `json:"n"`
```

### Iota resolution

In a const block, only the first spec has an explicit type. Subsequent specs inherit it:

```go
const (
    _ LockType = iota   // explicit type "LockType", value 0
    LockReadonly         // Type=nil (inherits "LockType"), iota=1
    LockUpdate           // inherits, iota=2
)
```

The parser tracks `currentTypeName` and `iotaCounter` across each const block. `containsIota()` recursively checks AST expressions for the `iota` identifier (handles `iota + 1`, `1 << iota`, etc.).

### Type resolution for struct fields

`resolveFieldType` recursively walks the AST expression:

```
*ast.Ident("string")   →  ("string", ptr=false, slice=false, map=false)
*ast.StarExpr(string)   →  ("string", ptr=true,  slice=false, map=false)
*ast.ArrayType(User)    →  ("User",   ptr=false, slice=true,  map=false)
*ast.MapType            →  ("map",    ptr=false, slice=false, map=true)
*ast.SelectorExpr       →  ("time.Time", ...)
*ast.ChanType           →  element type extracted
*ast.FuncType           →  ("Function", ...) + FuncSig parsed
```

`fullTypeString` renders the complete type expression back to a string for recursive conversion:

```
[][]int             → "[][]int"
map[string][]int    → "map[string][]int"
*[]string           → "*[]string"
```

### Function type parsing

`parseFuncType` extracts params and results from `*ast.FuncType`. Multi-name params are expanded:

```go
func(a, b int) → one Field with Names=[a,b], Type=int → two FuncParams
```

### Comment extraction

`extractComment` uses `ast.CommentGroup.Text()` which strips `//` prefixes and trims whitespace. Prefers spec-level comments over GenDecl-level. For struct fields, prefers inline comments (`.Comment`) over doc comments (`.Doc`).

### Generic type parameters

`parseTypeParams` reads from `ast.TypeSpec.TypeParams` (a `*ast.FieldList`). Each field can have multiple names sharing a constraint:

```go
[A, B any]        → two TypeParams with constraint "any"
[K comparable, V any] → two TypeParams with different constraints
```

`typeExprToString` converts constraint expressions to strings, handling `~int` (tilde), `int | int64` (union), and inline interfaces.

## Stage 3: Generation (`pkg/generator`)

### Generation flow for one source

```
generateSource(source, grouped)
│
├── Write header
│
├── Phase 1: Typed constants
│   for each TypeDef from this source file:
│   ├── shouldInclude()?
│   ├── Find consts of this type
│   ├── If no consts → writeTypeAlias()
│   ├── Resolve style (override > source > global)
│   ├── writeComment()
│   ├── switch style → writeUnion/writeEnum/writeConstObject
│   └── if values_array → writeValuesArray()
│
├── Phase 2: Untyped constants
│   for each const where TypeName == "":
│   ├── shouldInclude()?
│   └── writeStandaloneConst()
│
└── Phase 3: Structs
    for each StructDef:
    ├── shouldInclude()?
    ├── writeComment()
    ├── Collect embedded types → extends clause
    └── for each field:
        ├── Skip unexported, embedded, json:"-" (except func fields)
        ├── writeComment()
        ├── Resolve field name from struct tag
        ├── Handle pointer → optional "?"
        ├── Handle inline struct → writeInlineFields()
        ├── Handle function field → funcSigToTS()
        └── fullGoTypeToTS() for everything else
```

### Recursive type conversion (`fullGoTypeToTS`)

Handles nested composites by parsing the full type string:

```
"string"                       → goTypeToTS("string") → "string"
"*string"                      → strip * → recurse → "string"
"[]int"                        → strip [] → recurse("int") → "number" + "[]" → "number[]"
"[][]int"                      → strip [] → recurse("[]int") → "number[]" + "[]" → "number[][]"
"map[string]int"               → splitMapType → recurse key + val → "Record<string, number>"
"map[string][]int"             → splitMapType → key="string", val="[]int" → "Record<string, number[]>"
"map[string]map[string]string" → nested splitMapType → "Record<string, Record<string, string>>"
```

`splitMapType` handles nested brackets correctly by tracking depth.

### Function signature conversion (`funcSigToTS`)

- `context.Context` params stripped
- `error` returns stripped (TS uses exceptions)
- `error` as param type → `Error` (capitalized)
- Multiple non-error returns → tuple `[T1, T2]`
- No returns / only error → `void`
- Unnamed params → `arg0`, `arg1`, ...

### Prefix stripping

```
stripPrefix("MessageRoleUser", "MessageRole")
  1. HasPrefix? Yes
  2. Remainder: "User"
  3. Starts uppercase? Yes → "User"

stripPrefix("SomeOther", "S")
  1. HasPrefix? Yes
  2. Remainder: "omeOther"
  3. Starts uppercase? No → keep "SomeOther"
```

### Generic constraint mapping

```
"any"                         → no extends
"comparable"                  → extends string | number
"int | int64 | float64"       → isAllNumericConstraint → extends number
"~string"                     → isAllStringConstraint → extends string
```

## Design Decisions

### go/ast over regex

Handles all valid Go syntax. Gets exact type info from the compiler's own parser. Handles iota, multi-line strings, nested types, generics.

### Single ParseResult accumulator

Parser accumulates from multiple files into one result. Generator filters by source file path. Simpler than per-file results. Enables future cross-file references.

### String builder over templates

`strings.Builder` + `fmt.Fprintf` is simpler than Go templates for the current output complexity. Templates may be adopted if output grows more complex.

### YAML config as primary

Can reference files anywhere on disk (vendor, other repos, generated code). JSON Schema provides intellisense without custom tooling. Code-as-config is a possible future addition.

### Recursive fullGoTypeToTS

Flat flags (`IsSlice`, `IsMap`, `IsPointer`) can't represent `[][]int` or `map[string][]int`. The `FullType` string + recursive conversion handles arbitrary nesting.

### Function fields not skipped by json:"-"

Function fields with `json:"-"` are callbacks, not data. They're useful in TypeScript interfaces even though they're not JSON-serializable.
